# ADR-004 — نموذج الجلسة: Access في الذاكرة + Refresh دوّار في كوكي

**الحالة:** مقبول (2026-09)

## السياق
النظام القديم مرّر JWT في URL وخزّنه في localStorage (XSS يسرقه بسهولة) ولم يكشف إعادة الاستخدام.

## القرار
1. Access JWT قصير (15 دقيقة، HS256 + kid للتدوير) **في ذاكرة الصفحة فقط**.
2. Refresh عشوائي (256-bit) يُخزن **هاشداً**، في كوكي `HttpOnly; Secure(إنتاج); SameSite=Lax` scoped على `/api/v1/auth`.
3. تدوير إلزامي بكل استخدام؛ **إعادة استخدام رمية مكتشفة تُبطل كل جلسات المستخدم** وتُسجّل (`refresh_reuse_detected`).
4. استعادة صامتة للجلسة عند الإقلاع (POST /auth/refresh ثم /auth/me).

## العواقب
- ✅ سرقة كوكي واحدة تُكشف فور استخدامها الثانية وتُحتوى (blast radius = جلسة واحدة).
- ✅ لا شيء قابل للسرقة من storage أصلاً.
- ⚠️ انقطاع قصير للخدمة يُسقط الجلسة (مقبول مقابل الأمان) — Access قصير يخفف الأثر.
