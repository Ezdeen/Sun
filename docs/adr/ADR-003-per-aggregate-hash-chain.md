# ADR-003 — سلسلة هاش لكل كيان مع JSON قانوني

**الحالة:** مقبول (2026-09)

## السياق
النظام القديم استخدم سلسلة عالمية `ORDER BY id DESC LIMIT 1` فتفرّعت عند التزامن، ولم يخزّن الطابع الزمني المضمّن في الهاش فتعذّر إعادة التحقق، وولّد `anchor_ref` تشبه بلوك تشين وهمياً.

## القرار
1. سلسلة **لكل كيان** (request/shipment/bag) بتسلسل `seq` يبدأ من 1، مع `UNIQUE(aggregate_type, aggregate_id, seq)` وقفل صف الكيان قبل الإلحاق.
2. `occurred_at` (وكل حقول الإدخال) **مخزنة**، والهاش على **تسلسل قانوني**: JSON بمفاتيح مرتبة عودياً — وبما أن الترتيب مستقل عن ترتيب مفاتيح الإدخال، round-trip من jsonb لا يكسر التحقق (مثبت باختبار متجهات ذهبية + الرحلة E2E على PG حقيقي).
3. append-only عبر triggers في القاعدة (لا صلاحية تعديل/حذف حتى إدارياً).
4. `AnchorPort` واجهة فقط؛ التنفيذ الافتراضي NoOp بلا أي مرجع وهمي؛ جدول outbox لتجميع الجذور مستقبلاً.

## العواقب
- ✅ لا تفرّع تحت التزامن (مختبر بعبث فعلي مرفوض).
- ✅ `verify-chain` قابل للتشغيل في أي وقت من CLI أو واجهة المدير.
- ⚠️ أي تعديل مستقبلي على بنية الحدث يستلزم رفع `schema_version` (حقل موجود منذ اليوم الأول).
