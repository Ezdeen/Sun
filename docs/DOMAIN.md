# قواعد المجال (DOMAIN) والمسرد

## المسرد (الملحق أ.6)
| المصطلح | التعريف |
|---|---|
| **المواطن (citizen)** | مسلّم النفايات؛ يستحق حصة من عائد الصفقة. |
| **الجامع (collector)** | ينقل الأكياس من المواطن إلى منطقة الفرز. |
| **الهيئة المحلية (authority)** | بلدية/مجلس يوجّه الطلبات إلى الجامعين. |
| **منطقة الفرز (sorter)** | تستقبل الأكياس وتزنها وتجمّعها في صفقات. |
| **الطبقة المالية (finance)** | تبيع الصفقة (فاتورة) وتوزع المستحقات. |
| **المدير (manager)** | إدارة المنصة: الحسابات، الدعوات، الكتالوج، الإعدادات، التدقيق. |
| **الطلب (Request)** | طلب جمع من مواطن؛ دورة حياة: `received → sent_to_collector → on_the_way → arrived → collected → sorted → sold`. |
| **الكيس (Bag)** | وحدة مادية بباركود `BAG-…`؛ يُنشأ لكل سطر طلب. |
| **الصفقة (Shipment)** | دفعة أكياس تُباع بفاتورة واحدة. |
| **الفاتورة (Invoice)** | قيمة بيع الصفقة؛ تجمّد لقطة نسب التوزيع. |
| **المستحق (Payout)** | حصة مستفيد (منصة/جامع/مواطن) من فاتورة: `calculated → approved → paid` أو `→ void`. |
| **الدفتر (Ledger)** | قيود مالية append-only لكل حدث مالي. |
| **الهاش المركّب (CMP-…)** | هاش المواطن + الطلب — مفتاح التتبع العام. |

## قواعد التسعير (§6.1 — المحرك النقي `pricing/domain/pricing.ts`)
1. الوحدة `bottle`/`liter`: `الأساسي = سعر الوحدة × الكمية`؛ الوحدة `kg`: `سعر الوحدة × الوزن`.
2. **المكافآت التشجيعية**: تُجمع نسب الإضافات المتاحة للنوع فقط، بسقف `bonus_cap_percent` (25%). `السعر = الأساسي × (1 + النسبة/100)` بعد التخفيضات (ترتيب موثق A-001).
3. **`bulk_only`** (ورق ملوّث…): السعر 0 + تحذير «يُجمع بكيس منفصل».
4. **وزن الورق < الحد الأدنى** (5 كجم): السعر × عامل `paperUnderweightFactor` (0.5) + تحذير. عند الحد بالضبط: سعر كامل.
5. **كمية < 1**: سعر «تقديري مبدئي» × عامل `underUnitFactor` (0.5) + تحذير.
6. الوزن التقديري = الكمية × وزن الوحدة للأنواع المعدودة.
7. `price_per_ton` **مرجعي للبيع** ولا يدخل سعر المواطن.

اختبارات إلزامية: جدولية لكل قاعدة + حالات حدية (السقف بالضبط، الوزن = الحد، كمية 0) + خاصية «إضافة إضافة لا تخفض السعر أبداً».

## دورة حياة الطلب (§6.2 — `collection/domain/lifecycle.ts`)
- جدول الانتقالات **بيانات**: `received→(هيئة/مدير)→sent_to_collector→(جامع/مدير)→on_the_way→(جامع/مدير)→arrived→(جامع/مدير)→collected→(فرز/مدير)→sorted→(النظام فقط عبر الفاتورة)→sold`.
- لا قفز ولا رجوع (`409 invalid_transition`)؛ قفل متفائل `version` (`409 concurrent_update`).
- `on_the_way` يسند الجامع (حصرية؛ منع أخذ طلب مُسند لغيرك). `collected` يتطلب **مطابقة باركود المواطن** (qr/combined/request). `sorted` يتطلب **كل الأكياس موزونة ومربوطة**.
- تجاوز المدير: `reason` إلزامي للسجل؛ لا يلغي حراسات المال أو الباركود (A-008).
- الظهور: المواطن طلباته فقط؛ الجامع منطقته + المسند له؛ الهيئة منطقتها؛ الفرز/المالية/المدير الكل.

## التتبع (§6.3 — `traceability/domain/chain.ts`)
- حدث لكل تغيير: `{aggregate_type, aggregate_id, seq (لكل كيان), status_code, actor_role, actor_ref, payload, occurred_at (مخزن), prev_hash, event_hash, schema_version}`.
- `event_hash = SHA-256(canonical JSON)` مفاتيح مرتبة؛ أول حدث `prev_hash = GENESIS:<aggregate_id>`.
- `UNIQUE(aggregate_type, aggregate_id, seq)` + قفل صف الكيان أثناء الإلحاق = لا تفرّع.
- الجدول **append-only** (triggers ترفض UPDATE/DELETE) + `verify-chain` (CLI + API مدير) يعيد أول حدث مكسور.
- التتبع العام `GET /track/{CMP-…}` بلا مصادقة، محدود المعدل، **منقّح** (حالة/وقت/دور عربي فقط).
- `AnchorPort`: واجهة تثبيت خارجي؛ NoOp افتراضياً (لا مراجع وهمية)؛ جدول `outbox` جاهز لتجميع جذور Merkle.
- صيغ الباركود القديمة محفوظة: `CIT- COL- AUT- MGR- REQ- CMP- BAG-` (+ `SRT-/FIN-` للفرز/المالية و`SHP-/INV-` لأرقام الصفقات/الفواتير).

## التوزيع المالي (§6.4 — `finance/domain/distribution.ts`)
- النسب 30/40/30 (تُقرأ من الإعدادات، وتُجمَّد لقطةً على الفاتورة)؛ المجموع = 100 بالضبط (تحقق عند الحفظ).
- كل الحساب بوحدات صغرى صحيحة (أغورة) + **الباقي الأكبر** مع كسر التعادل بترتيب ثابت (حتمية تامة).
- `الوزن المعتمد = final_weight_kg` فقط؛ الأكياس غير الموزونة تمنع الفاتورة (`weights_missing`).
- حوض بلا مستحقين → سياسة `to_platform` (سطر دفتر صريح) أو `held` — **لا يُفقد مبلغ أبداً**.
- **الثابتة المبرهنة:** `Σ payouts (+held) == invoice.amount` بالضبط (اختبار خاصية 500 حالة).
- الإنشاء: معاملة واحدة (قفل صف + فريد جزئي للفاتورة الفعّالة + Idempotency-Key) تدفع الصفقة والطلبات إلى `sold` وتلحق أحداث السلسلة.
- المستحقات: `calculated→approved→paid | void(سبب)` للمالية/المدير فقط، وكل انتقال قيد دفتر مدقق.
- الدفتر append-only؛ التصحيح بقيد عكسي لا تعديل.

## الهوية والصلاحيات (§6.5)
- ستة أدوار؛ RBAC بصلاحيات صريحة (17 صلاحية) — لا مقارنة أسماء أدوار في المنطق.
- الهوية: `HMAC-SHA256(pepper, id)` + آخر 4 خانات؛ `CIT-…[:48]`.
- كلمات المرور: argon2id؛ سياسة قوة (10+ أحرف بأصناف أربعة).
- التسجيل الذاتي للمواطن خلف علم؛ بقية الأدوار بدعوات لمرة واحدة؛ **المدير الأول عبر CLI فقط**.
